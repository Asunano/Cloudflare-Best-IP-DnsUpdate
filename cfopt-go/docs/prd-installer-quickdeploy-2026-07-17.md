## 0. 背景与边界（给架构师的前置约束）

### 0.1 本次目标（一句话）
让 cfopt-go 从「给示例配置 + 教命令」变成「向导引导 + 自动落盘 + 一键部署」，实现**下载即上手**。

### 0.2 已拍板的两项决策（必须遵守）
1. **主界面形态 = 终端问答菜单**：用标准输入问答复刻 bash 数字菜单循环，**不引入 TUI 库**，跨平台最稳；`cfopt` 无参即进主菜单。下载二进制即可用，不构建 GUI。
2. **实现范围 = MVP 闭环**：`install` + 主菜单 + `quickdeploy`（单域名，但支持单/多线路）+ 自更新增强 + 卸载，先把「下载即上手」跑通。

### 0.3 非目标 / 限制（务必纳入设计）
- 全程**不用 git**；**不兼容**旧 Bash 版 `cfopt.sh`（本次是「对齐功能」非「兼容」）。
- **不改动 IPC / Tauri GUI 既有行为**：终端菜单/向导与 GUI 并存、互不干扰；GUI 仍用单值配置（多域名仅走文件，GUI 不改）。
- 沙箱能编 Go，但**不能编 Rust/Node**（无法构建 Tauri GUI）——与「终端菜单」决策一致，本次不碰前端。
- 用户运行环境是 **Windows + cmd/PowerShell**（非 Git Bash）；Go 二进制跨平台，但**任何生成的脚本/命令不要写 bash 专属语法**（`$(...)`、`printf`、管道 `nc` 等）。
- `cfopt cfst fetch` 与 `cfopt update` **已有，增强复用，不推翻重写**。

### 0.4 可复用的既有能力（不要重复造）
| 既有命令/模块 | 用途 | 本次如何使用 |
|---|---|---|
| `cfopt cfst fetch` | 下载 cfst 二进制 + SHA256 校验 | `install` 触发调用，复用 |
| `cfopt update` | 自更新（哈希比对 + 原子替换 + 重启） | 增强 `--check`，复用原子替换 |
| `internal/scheduler` + `daemon`（kardianos/service） | systemd/cron 安装启停 | `schedule install/uninstall/start/stop/status` 被 `install`/`quickdeploy`/调度中心包装 |
| `conf/dnspod\|cf-dns/<域名>.conf` 扫描加载 | 多域名加载 | `quickdeploy`/`config wizard` 生成文件，复用加载逻辑 |
| `cfopt sync` / `cfopt speedtest` | 同步 / 测速 | `quickdeploy` 自动串联调用 |

## 1. 产品目标

**让 cfopt-go 从「给示例配置 + 教命令」变成「向导引导 + 自动落盘 + 一键部署」，把「教用户怎么做」升级为「帮用户怎么做」，降低新手的上手门槛，实现下载即上手。**

三个正交的子目标：
1. **零配置启动**：下载二进制 → 无参运行即进菜单，不再要求先读 README、手编 JSON。
2. **向导式落盘**：跟着向导填 Token 即自动校验、取 Zone ID、生成 600 权限配置，不再有 `your_api_token_here` 占位符卡住 sync。
3. **一键闭环**：安装（自安置+全局命令+调度）、部署（quickdeploy）、卸载（干净清理）形成闭环，运维可标准化批量铺机。

## 3. 需求池（P0 / P1 / P2）

> 优先级：P0=Must（MVP 必须）、P1=Should（增强）、P2=Nice to have。
> 每条含：编号、标题、描述、验收标准。

### P0 — MVP 必须

#### P0-1 `cfopt install` 自安置与全局命令
- **描述**：一条命令完成二进制自安置到固定目录、创建全局命令（Windows 方案见待确认 Q1）、触发既有 `cfopt cfst fetch` 下载 cfst 二进制 + SHA256 校验、生成默认 conf 目录骨架（`conf/`、`conf/cf-dns/`、`conf/dnspod/`、`assets/data/`）。必要时做轻量网络体检（仅探测可达性，不阻塞）。
- **验收标准**：
  - 运行后二进制位于固定目录，新开终端可直接调用全局 `cfopt` 命令。
  - 自动调用既有 `cfopt cfst fetch` 完成 cfst 下载与校验（复用，不重写）。
  - 生成 conf 目录骨架与默认 global 配置（占位符明确标注「稍后由向导填写」）。
  - 网络体检仅做可达性探测，失败仅警告、不中断安装。
  - **幂等**：重复运行不破坏已有用户配置。

#### P0-2 `cfopt` 无参主菜单（问答循环）
- **描述**：当无子命令参数时进入终端问答式数字菜单循环（标准输入读取，不引入 TUI 库）。菜单项见 §4，至少含 快速部署 / 配置向导 / 卸载，循环至用户选 0 退出。
- **验收标准**：
  - `cfopt` 无参运行即打印主菜单并等待输入。
  - 输入数字执行对应功能，执行完返回主菜单（循环）。
  - 输入非法值提示重输；输入 0 干净退出（退出码 0）。
  - 非交互终端（管道/重定向）时打印用法提示而非卡死。

#### P0-3 `cfopt quickdeploy` 单域名向导（CF/DNSPod，单/多线路）
- **描述**：把「手编 3 个 JSON → 手填密钥 → 手跑测速 → 手配 cron → 手跑 sync」五步压成一次向导：静默输 Token → API 校验并自动取 Zone ID/域名 → 生成 conf → 首次 speedtest → sync → 安装调度 → 登记。支持单线路与多线路（多线路输入简化见 Q3）。
- **验收标准**：
  - 向导覆盖 Cloudflare 与 DNSPod 两种服务商。
  - Token **静默输入**（不回显）；凭证错误时明确报错并可重试。
  - 自动校验凭证并取回 Zone ID 与域名列表供选择。
  - 生成对应 conf 文件（权限 600），内容可直接被 `sync` 消费。
  - 自动串联 speedtest → sync → schedule install/start，全程无需手敲命令。
  - 结束时打印部署摘要（域名、线路、调度状态）。

#### P0-4 替换空壳 `config wizard` 为真正问答式配置生成
- **描述**：重写 `cfopt config wizard`，实现真正的表单逻辑：选服务商 → 静默输凭证 → API 校验 → 自动取 Zone ID/域名 → 选线路（单/多）→ 落盘 conf。覆盖 CF/DNSPod，单/多线路。
- **验收标准**：
  - 交互终端下能逐项引导并**真正写入配置**（非仅打印「请编辑」）。
  - 非交互终端给出明确手动指引（保留现有降级行为）。
  - 生成的 conf 通过 `cfopt config validate`。
  - 与 `quickdeploy` **共享**凭证校验/取 Zone ID 逻辑（避免重复实现）。

#### P0-5 `cfopt uninstall` 交互确认清理
- **描述**：交互确认（yes/no）后清理全局命令、已安装调度（`schedule uninstall`）、conf 与数据目录（可选保留配置）。清理范围不含 PATH/别名/cron 之外的无关文件。
- **验收标准**：
  - 执行前必须交互确认，**默认不清理**（防误删）。
  - 清理全局命令软链/注册、停止并卸载调度。
  - 提供「保留配置 / 全清」选项。
  - 清理后打印已移除项清单；失败项明确列出，不静默跳过。

### P1 — 增强（Should）

#### P1-1 `cfopt update --check` 增强 / 自更新体验打磨
- **描述**：在既有 `cfopt update`（哈希比对 + 原子替换 + 重启）基础上，增强 `--check` 仅检查不更新，并在主菜单「检查更新」展示版本差异与变更说明；更新过程给进度与回滚提示。
- **验收标准**：
  - `cfopt update --check` 返回是否有新版本及版本号，不触发替换。
  - 主菜单「检查更新」展示当前/最新版本与简要变更。
  - 复用既有原子替换逻辑，不重写。

#### P1-2 主菜单「调度中心」子菜单（包装 schedule）
- **描述**：在主菜单增加「调度中心」，包装既有 `cfopt schedule install/start/stop/status/uninstall`，提供状态查看与启停，降低记忆成本。
- **验收标准**：
  - 子菜单可显示当前调度状态（运行中 / 已停止 / 未安装）。
  - 支持安装/启动/停止/卸载调度，底层复用 `cfopt schedule`。
  - 操作结果明确反馈。

#### P1-3 多域名快速部署
- **描述**：在 `quickdeploy` 基础上支持一轮内部署多个域名（循环添加或批量列表），每个域名独立生成 conf 并统一调度。
- **验收标准**：
  - 一次向导可添加 N 个域名，逐个走校验 + 落盘。
  - 多域名共享一次 speedtest 与统一调度。
  - 部署摘要列出全部域名状态。

### P2 — 可选（Nice to have）

#### P2-1 轻量 `cfopt doctor` 健康检测
- **描述**：检测配置完整性、cfst 二进制存在性、调度状态、网络可达性，输出健康报告与一键修复建议。
- **验收标准**：输出各项检查通过/失败状态；对常见失败给修复建议；**只诊断不修改**配置。

#### P2-2 引导里「自动探测最佳测速节点」
- **描述**：在 quickdeploy/配置向导的测速环节，自动从候选节点列表探测延迟最低的节点，减少手动选节点。
- **验收标准**：自动选取延迟最低节点用于 speedtest；用户可覆盖手动指定。

#### P2-3 安装时可选装系统服务
- **描述**：`cfopt install` 增加可选步骤，将自身注册为系统服务（复用 kardianos/service），开机自启。
- **验收标准**：安装时可选择是否注册系统服务；复用既有 service 能力；卸载时同步清理。

## 4. 终端菜单树 / 交互设计稿

### 4.1 `cfopt` 无参主菜单（问答循环）

```
┌──────────────────────────────────────────────────────┐
│            cfopt 主菜单  (vX.Y.Z)                     │
│  1) 快速部署        [P0] → cfopt quickdeploy 向导      │
│  2) 配置向导        [P0] → cfopt config wizard 真表单 │
│  3) 调度中心        [P1] → 包装 cfopt schedule        │
│  4) 检查更新        [P1] → cfopt update --check       │
│  5) 健康检测        [P2] → cfopt doctor              │
│  9) 卸载 cfopt      [P0] → cfopt uninstall           │
│  0) 退出                                            │
└──────────────────────────────────────────────────────┘
   请输入序号 [0-9]: █
```
- 选 1/2/3/4/5 执行后返回主菜单（循环）；选 9 进入卸载确认；选 0 退出。
- 非交互终端：打印上述菜单 + 用法即退出，不阻塞。

### 4.2 子菜单分支

```
1) 快速部署
   └─→ 直接进入 quickdeploy 向导（见 4.3）

2) 配置向导  (config wizard 真表单)
   ├─ 选择服务商: 1=Cloudflare / 2=DNSPod
   ├─ 静默输入 Token / SecretID+SecretKey
   ├─ [程序自动] API 校验 + 取回 Zone/域名列表
   ├─ 选择域名（默认第一个，可列表选）
   ├─ 选择线路: 单线路 / 多线路（见 Q3）
   └─ [程序自动] 落盘 conf/<服务商>/<域名>.conf (600) → 返回主菜单

3) 调度中心  [P1]
   ├─ 显示状态: 运行中 / 已停止 / 未安装
   ├─ [1] 安装并启动   → cfopt schedule install + start
   ├─ [2] 停止         → cfopt schedule stop
   ├─ [3] 查看状态     → cfopt schedule status
   ├─ [4] 卸载         → cfopt schedule uninstall
   └─ [0] 返回主菜单

4) 检查更新  [P1]
   └─→ cfopt update --check → 展示 当前/最新版本 + 变更 → 询问是否更新 [Y/n]

5) 健康检测  [P2]
   └─→ cfopt doctor → 输出检查项报告 + 修复建议

9) 卸载
   ├─ 确认: 确定卸载 cfopt 吗? [y/N]  (默认 N，防误删)
   ├─ 选择: [1] 全清 / [2] 保留配置
   └─ [程序自动] 停止+卸载调度 → 移除全局命令 → 清目录 → 打印清单
```

### 4.3 `quickdeploy` 逐步交互稿（单域名，支持单/多线路）

| 步骤 | 用户输入 | 程序自动做什么 | 产出文件 / 状态 |
|---|---|---|---|
| 0 选服务商 | `1`=Cloudflare / `2`=DNSPod | 分支后续逻辑 | — |
| 1 输入凭证 | Token（**静默不回显**） | 调用 API 校验有效性；失败报错可重试 | — |
| 2 取域名 | 选序号或默认首域名 | 拉取可用 Zone/域名列表 + 取回 Zone ID | — |
| 3 选线路 | 单线路 / 多线路（输入见 Q3） | 组装线路配置 | — |
| 4 生成配置 | （无需输入，默认全 Y） | 写 `conf/cf-dns/<域名>.conf` 或 `conf/dnspod/<域名>.conf`（权限 600） | `*.conf` |
| 5 首次测速 | （无需输入） | 触发 `speedtest` → 产出 `best.iplist` | `best.iplist` |
| 6 首次同步 | （无需输入） | 触发 `sync` 把优选 IP 写入 DNS 记录 | DNS 记录更新 |
| 7 安装调度 | （默认 Y） | `schedule install` + `start`（频率见 Q2） | 计划任务/服务 |
| 8 登记完成 | — | 打印部署摘要（域名/线路/调度状态），返回主菜单 | — |

> 设计原则：除「服务商 / 凭证 / 域名 / 线路」四项必须输入外，其余步骤默认全 Y（回车即过），对齐 bash 版「几次回车完成部署」。

## 6. 验收总览（MVP 闭环定义）

当以下全部达成，视为本次增量 MVP 闭环完成：
- [ ] `cfopt`（无参）→ 主菜单可循环进入。
- [ ] `cfopt install` 一条命令完成自安置 + 全局命令 + cfst 下载 + conf 骨架，幂等。
- [ ] `cfopt quickdeploy` 单域名（单/多线路）向导，静默 Token → 自动校验取 Zone ID → 落盘 600 conf → speedtest → sync → 调度，全程无需手敲命令。
- [ ] `cfopt config wizard` 真正写入配置（非空壳），且 `config validate` 通过。
- [ ] `cfopt uninstall` 交互确认后干净清理，零残留。
- [ ] IPC / Tauri GUI 既有行为未被改动；无 bash 专属语法；未触碰 Rust/Node。
